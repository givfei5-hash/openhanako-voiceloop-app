# Voiceloop 语音播报

给 HanaAgent 一个声音：开场轻问候、过程贴状态旁白、收尾把最终输出念出来。关屏、走开、睡觉，也能听到活干到哪了、结果是什么。

Hana v2 应用（`manifestVersion: 2`），当前版本 8.4.6。

## 安装与生效

首次安装或更新本应用后，需要**完全重启 HanaAgent**（退出后重新打开，而不是只重载应用）才会生效——应用进程与 hook 注册在 Hana 启动时完成。重启之后，设置页里的改动实时生效，不必再次重启。

## 它做什么

- **新会话自动开场**：应用挂在新会话首个回合的开始钩子（`agent/before-start`，按会话去重）上，会话一开就自动播一句轻问候，**不依赖 Agent 是否记得调用**。问候一律**由模型现写**：读你的第一句话，现写一句贴任务的开场（跟随「播报风格」设置）。生成分两跳、越靠前越快——先试宿主工具模型（2.5 秒超时，**快速切换**），不可用或超时立即改用当前会话正在用的主模型。**没有兜底固定句**：两跳都拿不到就不播（静默），不拿罐头话凑数
- **收尾自动播**：应用在 `messages/post-assistant` 上只「记下」本轮最后一条纯文本回复，真正的播报等到 `agent/settled`（回合真正结束）才发——否则一轮里多条纯文本各播一遍，听起来就是“复读”。短则整段念，长则先让模型压成 180 字以内的口播稿。这条与开场一样，是应用硬保证的
- **过程旁白自动兜底**：应用在 `tools/post-execute` 上按「播报密度」计数（紧凑每 1 步、标准每 2 步、稀疏每 4 步、安静不播）自己播一句短状态；一次只让一句在响，**最近一次出声到本档位间隔（8/12/16 秒）内就不补**，所以不会叠声、不会重复
- **四档合成策略**（设置页下拉，默认「云端优先 + 本地兜底」）：
  1. **云端 Edge TTS 优先**：只走微软云语音，网络正常时约 1 秒出声；**5 秒不出声就切走**，不硬等；断网时静默
  2. **云端优先 + 本地兜底（默认）**：edge 超时/断网时自动切非 edge 链路
  3. **只用本地/自建 TTS API**：不经过 edge-tts/微软（注：豆包媒体引擎是云服务，严格零出网请选「自配置」并指向本地部署的 API）
  4. **HanaAgent 媒体引擎专属**：纯内部管线，只走 Hana 媒体引擎（豆包 TTS），不走微软 TTS、不走本地模型；引擎不可用时直接报失败，不回退
- **非 edge 链路两种来源**（设置页下拉）：
  - **HanaAgent 内置媒体引擎**：豆包 TTS，零配置，用 Hana 里已配置的 TTS 供应商（设置 → 媒体/TTS）
  - **自配置标准 OpenAI 兼容 TTS API**：Base URL + 模型名 + API Key 三字段，本地模型（`scripts/tts_server.py` 包装，默认 `http://127.0.0.1:8137/v1`）或任何第三方 TTS 服务都能接。本地部署由 llama.cpp + Qwen3-TTS 1.7B GGUF（Q4_K_M）驱动，`GET /health` 可查状态
- **参考音随包预合成**：6 个音色的参考音频已打包在 `refs/` 目录（晓晓/云希/晓伊/云健/云扬/云夏，16k 单声道 wav），换音色即换声，不等不联网。云端认声音名、本地 API 认参考音克隆，同一选项两路同声（媒体引擎用自己的音色体系）
- **音色两套**：edge-tts/自配置 API 用 `voice`（晓晓默认 / 云希 / 晓伊 / 云健 / 云扬 / 云夏，同一选项两路同声）；豆包媒体引擎用 `mediaVoice`（俏皮女声默认 / 小何 / 邻家女孩 / 暖阳女声等 16 选，从 445 音色表挑的中文常用，仅豆包引擎生效）
- **播报纪律随包**：`skills/voiceloop/SKILL.md` 定义了开场问候、回合起手、慢步骤预告、改道/受阻、里程碑、收尾念最终输出的完整风格与克制规则（含播报风格四档：俏皮/平实/温柔/干练，事实优先红线通用），Agent 自动遵守
- **敏感内容红线**：密码、密钥、证件号等一律不播
- **设置页**（设置 → 应用 → Voiceloop 语音播报）：
  - 总开关：一键静音
  - **新会话自动开场播报**：开关（默认开 = 会话开始时由模型按你的第一句话现写一句开场并播报，不依赖 Agent；关 = 不开场，需要时由 Agent 自己播）
  - **播报密度**：四档——紧凑（每个工具步都可能报）/ 标准（每两步一句，默认）/ 稀疏（每四步一句，话很少）/ 安静（过程不播，只留开场+收尾）。**由应用按工具步数硬控**，不依赖助手自己数
  - **播报风格**：四档，同时决定**语气与长短**——俏皮（默认，约 140 字）/ 平实（约 80 字）/ 温柔（约 220 字）/ 干练（约 100 字）。长短指收尾一次念多长
  - **语音 TTS 合成策略**：三档下拉（见上）
  - **播报密度**：四档——紧凑（每个小节推进都报，回合 6~8 句）/ 标准（每 2 个实质步骤 1 句，默认）/ 稀疏（每 4 个步骤 1 句，话最少）/ 安静（只开场 + 收尾）。每次播报的返回会带回当前档位，Agent 据此执行
  - **播报风格**：四档下拉——俏皮（默认，活泼概括、可自嘲、事实优先）/ 平实（不修饰、只报事实、词最少）/ 温柔（语气更软、更关心）/ 干练（短句、信息密度高、不寒暄）。风格只改说法，纪律不随风格变
  - **巡检/定时监控任务全程静默**：开关（默认开 = 巡检全程静默、只在发现问题时播一句；关 = 按正常播报纪律执行）
  - **音色**：6 选下拉（edge-tts + 自配置 API 同一音色）
  - **豆包媒体引擎音色**：16 选下拉（俏皮女声默认 / 小何 / 邻家女孩 / 暖阳女声 / 贴心女声 / 清新女声 / 温柔淑女 / 知性灿灿 / 流畅女声 / 开朗姐姐 / 甜美小源 / 儒雅逸辰 / 深夜播客 / 高冷沉稳 / 阳光青年 / 小天；仅豆包引擎生效，完整 445 音色表在 Hana 媒体目录）
  - **语速**：+20% / +15%（默认）/ +10% / 0 / -10% 下拉
  - **非 edge 链路的 TTS 来源**：两选下拉——自配置 TTS API（本地模型/第三方服务）/ HanaAgent 内置媒体引擎（豆包 TTS，零配置）
  - **TTS API 地址 / 模型名 / API Key**：标准 OpenAI 兼容 API 三字段（仅「自配置」来源生效；API Key 掩码显示）
  - Python 命令：技术字段，一般不用动

## 安装要求

| 依赖 | 用途 | 必装 |
|---|---|---|
| Python 3.10+ | 运行随包 `speak.py` 与 `tts_server.py` | 是 |
| `edge-tts`（`pip install edge-tts`） | 云端引擎（edge / edge-local 策略需要） | 选「只用本地/自建 TTS API」策略时不需要 |
| `ffmpeg` / `ffplay`（`winget install ffmpeg.ffmpeg`） | 播放合成的音频 | 是 |
| 本地 TTS API（tts_server.py） | 非 edge 链路的出声来源 | 否（没有也能用，只是本地链路不可用） |

### 本地克隆音质配方（2026-10-09 定稿）

本地 API 出来的声音要跟云端“同一个人、同一个清新度”，靠的是这套参数（踩过坑，别再改回去）：

| 项 | 值 | 为什么 |
|---|---|---|
| 参考音采样率 | **24 kHz** | 引擎原生输出就是 24k；参考音用 16k 会让克隆学到被砍掉高频的音色 → 发闷 |
| 参考音来源 | 云端 edge **原生 +15%** 录制 | 不用 ffmpeg 拉伸（atempo 会给音色上色） |
| 参考音素材 | 活泼口语（短句/问句/感叹） | 克隆学的是参考音的语气；素材平，出来就平 |
| 参考音时长 | 50 秒左右 | 越长越像 |
| 响度处理 | **不做** loudnorm | 归一虽然对齐了电平，但会压掉高频，换来的通透更值 |
| 引擎采样 | temp **0.4** / top-k 20 / top-p 0.9 / 关重复惩罚 | 越低温越贴参考音；0.4 是“像”与“有起伏”的甜点位 |
| 语速 | 云端 `+15%` ≡ 本地 `speed 1.15` | 两路同速，听感才一致 |

生成参考音：`py scripts/gen_ref_lively.py [音色名]`（默认晓晓）——按上面规格生成并铺到 `refs/`、`ref/`、`models/`。
采样参数服务端可按请求覆盖：POST `/v1/audio/speech` 带 `temperature` 即可（用于现场 A/B）。

### 本地 TTS API 部署（可选，推荐）

应用**不直连本地模型**——本地链路只有一条：把模型部成标准 OpenAI 兼容 TTS API，应用连它出声。分发到不同用户时，链路就是「部好模型 → 露出 API → 在设置页填 Base URL」。

1. **本地 TTS API**：`scripts/tts_server.py`，把本地引擎包装成 OpenAI 兼容 TTS API，参考音从自身目录 `refs/` 读（随包 6 个音色）。启动它之后，断网、edge 抽风都还有声音。

部署方式：把 `scripts/tts_server.py` + 引擎目录（`llama/` + `models/`）+ 本应用 `refs/` 放到同一个目录（如 `tts-local/`），`tts_server.py` 会自动识别自身目录为引擎目录，无需环境变量。然后：

```
# 手动启动（最小化窗口运行）
start-tts-api.bat        # 或在引擎目录直接: py tts_server.py --port 8137

# 开机自启
start-tts-api.vbs        # 放进 Windows 启动文件夹（%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup）
```

验证：浏览器访问 `http://127.0.0.1:8137/health`，看到 `"engine": "ready"`、`"refs": 6` 即可。

## 工作原理

Agent 调用 `voiceloop_speak` 工具（参数 `text`，可选 `voice`/`rate`）→ 应用进程按设置编排链路，逐段尝试、第一个成功就播：

- `edge`：edge-tts（speak.py `--engine edge`，8s 超时）
- `edge-local`：edge-tts → 非 edge 来源（默认）
- `local`：只走非 edge 来源，不试云端
- `media`：只走 Hana 媒体引擎（纯内部管线，无回退）

非 edge 来源：选「自配置」时 speak.py `--engine api` 打 OpenAI 兼容 API（Base URL/模型/Key 来自设置页）；选「Hana 媒体引擎」时应用进程调 Hana 媒体总线 `media:generate-speech`（豆包 TTS，音色传设置页 `mediaVoice`），轮询任务完成后把音频交给 speak.py `--play` 播放。

合成/取回后用 ffplay 静默播放（本地路径 1.15 倍速对齐云端 +15%）→ 退出码 0/2/3 映射成给 Agent 的结果与排障提示，返回里带实际走的引擎名与各段失败原因。分段超时：edge 8s、API 120s、媒体引擎 60s。

## 权限

- `app/tools.expose-to-model`：把 `voiceloop_speak` 暴露给 Agent
- `app/process.spawn`：spawn 本机 Python 运行 speak.py（合成与播放都在 OS 层完成）
- `app/hooks.agent-before-start`：挂在会话首回合的钩子上，用于新会话自动开场播报
- `app/hooks.messages-post-assistant`：记下本轮最终回复，用于收尾自动播报
- `app/hooks.tools-post-execute`：工具跑完计数，用于过程旁白自动兜底
- `app/hooks.observe` / `app/models.infer` / `app/sessions.read`：自动开场/收尾时读会话上下文、调模型现写开场或压口播稿
- `app/models.read` / `app/media.generate`：「Hana 媒体引擎（豆包 TTS）」来源必须的两项能力——前者读供应商/模型目录（没配默认语音模型时应用靠它自己发现豆包，否则这条链会直接报「没有可用的 TTS 供应商」），后者才是真正调 `media:generate-speech` 合成。**缺这两项时豆包这句话就发不出声**
- 媒体总线：「Hana 媒体引擎」来源通过 Hana 媒体能力合成（`media:generate-speech`），凭据由 Hana 统一管理，本应用不存任何 TTS 密钥（自配置来源的 API Key 存在应用设置里，掩码显示）

## 隐私

- 选「只用本地/自建 API」：文本只发给设置页里那个 API（本地部署时只监听 127.0.0.1，不出本机）
- 选「媒体引擎」：文本发给 Hana 配置的 TTS 供应商（如豆包），不出微软
- 选云端相关策略：edge-tts 合成请求发给微软 TTS 服务，失败后按来源（TTS API / 媒体引擎）走
- 不落盘任何历史文本（合成产物写在系统临时目录，播完即删；媒体引擎产物由 Hana 媒体任务管理）
